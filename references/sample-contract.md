# HTML 样张契约

## 公平比较

统一产品内容、主要任务、信息范围、语言和视口；不统一 DOM、Hero、卡片数、图片比例、列数、留白和视觉编排。布局本身属于风格，禁止同模板换色。

样张覆盖一个代表性主场景和 2–4 个真实会用的组件。至少有主/次操作和键盘焦点；表单场景要有 label、错误/禁用状态。原规范缺失必需状态时，先按 adjustment 规则补足候选规范。

## 文件与安全

- 默认单入口 `sample.html`，CSS 内联；只用少量无外发行为的 JS。
- 不依赖 React、构建工具、远程 JS，不提交真实表单、不埋点、不上传数据。
- 用户合法素材可放候选 `assets/` 并使用相对路径。
- 不自动下载品牌 Logo、官网图片或未授权字体。
- 用户文案必须做 HTML/属性/URL 对应转义；不能直接拼入 innerHTML。
- 可用 file://；自动化需要服务时仅绑定 localhost、根目录限于候选，并在结束后停止服务。

## 字体与中文

顺序：授权且可加载原字体 → 原规范明确替代 → 告知用户后的最接近替代。替代先写入候选 typography 和正文，列出角色、字重、行高、tracking；中文必须指定 CJK fallback。CSS fallback 不等于原字体已加载。

## 响应式

默认真实检查 375、768、1440 CSS px。先读 Responsive Behavior 和 Layout。普通 375px div 不能代替真实 viewport。检查横向溢出、文字截断、导航折叠、按钮触达、表格/代码有意滚动、图片裁切和阅读顺序。

若原文没断点，为当前内容添加最小必要项目适配并写回规范；需要大幅重构则换候选。

## 内容真实性

使用产品相关、具体可读内容。无真实业务数字时标记“示例数据”或“待确认文案”；不伪造客户、证言、营收、用户数、安全认证或合规承诺。候选之间保持同一内容清单。
